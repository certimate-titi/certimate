## 0. 問題定義與設計哲學

### 0.1 Orphan 節點是什麼

「Orphan 節點」指知識心智圖中存在（因考綱逆向工程或 unified extraction 生成），但無任何教材鷹架（scaffold_node_links 關聯數 = 0）的知識節點。依現況監控目標，orphan node 比率應控制在 20% 以內（depth=2 節點）。

超出此比率的場景下，學生在心智圖中看到「⚠️ 遺漏」警示但找不到任何學習路徑，形成 **知識焦慮陷阱**（knowledge anxiety trap）：可見卻不可達的缺口，比完全不知道更損害學習動機（Bandura self-efficacy theory, 1989）。

### 0.2 設計哲學三原則

1. **誠實但不絕望**：永遠告知學生覆蓋率現狀，但立即給出可行的下一步。
2. **品質勝於覆蓋率**（沿用 node-scaffold-pipeline-redesign 原則）：寧可一個節點顯示「AI 推論鷹架」amber 邊框，也不要顯示無關鷹架。誤導比缺漏的學習傷害更大（Chi, 1994, misconception persistence）。
3. **游戲化是手段，不是目的**：完成度框架的徽章與進度條必須服務於 mastery，一旦驅動行為背離 mastery（如只追徽章不補弱點），系統必須介入糾正。

## 區塊 A — #2 AI 自動補洞鷹架設計規範

### A.1 觸發條件：哪種 Orphan 節點才自動補洞

並非所有 orphan 節點都值得生成 AI 補洞鷹架。以下為分層觸發邏輯：

#### A.1.1 必要條件（AND 關係，全部滿足才觸發）

| 條件 | 門檻 | 說明 |
|------|------|------|
| 節點深度 | depth = 2（section 層）| depth=1 chapter 太抽象，AI 反推效果差 |
| 科目考古題數量 | ≥ 30 題 | 佐證題庫不足無法反推，直接不生成 |
| 節點出題頻率 | 在現有考古題中命中 ≥ 1 次（含模糊比對） | 完全沒出過題的節點優先讓學生跳過 |
| scaffold_node_links | 關聯鷹架數 = 0（純 orphan）| 已有鷹架的節點不觸發 |

#### A.1.2 優先級加分（決定佇列順序）

| 加分因素 | 分數 |
|---------|------|
| 節點出題頻率在科目前 30% | +3 |
| 節點在相鄰節點的 cosine 圖中距離 ≥ 3 個鄰居（孤島節點）| +2 |
| 學生已嘗試答題但錯誤率 ≥ 60% | +3 |
| 距離考試日期 ≤ 30 天 | +2 |

加分總分 ≥ 5 才進「高優先生成佇列」；< 5 則進「背景低優先佇列」（不影響即時體驗）。

#### A.1.3 強制不觸發（排除紅線）

- 考古題佐證數 < 3 題（對應節點名稱的精確比對）：不生成，顯示「佐證題不足，無法自動補洞」灰底提示。
- 科目考古題總數 < 30 題：整個科目不啟用此機制。
- 已有人工審核打標「incorrect」的 AI 鷹架在等候中：不再重複生成，等人工修正完成後再評估。

### A.2 內容結構：retrieval-first 補洞模板

**模板名稱**：`K-ORPHAN-01`（對應 scaffold-redesign-plan 中的模板矩陣體系）

每份 AI 補洞鷹架包含以下三段，嚴格限制字數：

#### 段落一：定義（Definition）

- **字數上限**：120 字
- **格式**：一段話，無條列
- **內容要求**：必須呼應節點名稱，用考古題中出現的用語定義（不得憑空發明）
- **引用標示**：每個關鍵術語後標 `[考古題#題號]`，例如 `信義原則 [考古題#2024-Q47]`

#### 段落二：範例（Illustration）

- **字數上限**：200 字
- **格式**：一個具體情境或計算範例（視科目而定）
- **引用標示**：若直接改編自考古題，標 `（改編自 {年份} 第 {X} 題）`
- **不得包含**：完整的原始考古題文字（著作權風險）

#### 段落三：一道練習題（Retrieval Practice）

- **字數上限**：150 字（題目 + 4 個選項）
- **格式**：單選題，A / B / C / D 四選項
- **答案揭示**：預設摺疊，學生點「揭曉答案」後才展開（對應 E1 retrieval UI 設計）
- **解析字數上限**：100 字（聚焦在「為什麼 A 對、為什麼 B 錯」）
- **難度標記**：依既有階層式難度遞進（Feature 28）標 T1 / T2 / T3

### A.3 信任度標示系統

#### A.3.1 視覺識別

```
amber 邊框（#F59E0B，border-width: 2px）
右上角角標：「AI 推論」小徽章（amber 背景、白字）
```

與既有「正式教材鷹架」（無特殊邊框）和「教師審核通過鷹架」（綠色 ✓ 角標）明確區隔。

#### A.3.2 浮水印文字（常駐顯示，不可關閉）

```
此鷹架由 AI 從考古題反推生成，尚未經教師人工審核。
引用佐證：{N} 道考古題（{年份範圍}）
信心分數：{score}/100
```

#### A.3.3 信心分數計算公式

```
信心分數 = (佐證題數 × 10) × 精確命中率 × (1 - 節點距離衰減)

其中：
  佐證題數   = 對應節點名稱精確命中的考古題數（上限計 8 題，8 題以上不再加分）
  精確命中率 = 佐證題中節點名稱精確出現（vs 模糊出現）的比率，範圍 0.5–1.0
  節點距離衰減 = 若鷹架內容來自鄰居節點 embedding 推導（非直接命中），乘以 0.8

示例：
  佐證題數 = 5，精確命中率 = 0.8，無距離衰減
  信心分數 = (5 × 10) × 0.8 × 1.0 = 40
  → 顯示 40/100（灰底警告區間）

  佐證題數 = 8，精確命中率 = 1.0，無距離衰減
  信心分數 = (8 × 10) × 1.0 × 1.0 = 80
  → 顯示 80/100（正常 amber 邊框顯示）
```

#### A.3.4 信心分數對應 UI

| 分數範圍 | UI 狀態 | 說明 |
|---------|--------|------|
| 0–30 | 不生成 | 直接顯示「佐證不足」灰底提示 |
| 31–49 | 灰底 amber 邊框 + 警告文字「AI 信心低，建議搭配其他資源」| 呈現但強烈標記 |
| 50–79 | 標準 amber 邊框 | 正常顯示，浮水印常駐 |
| 80–100 | amber 邊框 + 「佐證充足」小標 | 最高信心，仍非正式教材 |

### A.4 退出機制：學生標記不準確

#### A.4.1 觸發入口

每份 AI 補洞鷹架底部固定顯示：「這份內容有問題嗎？ [標記不準確]」按鈕（ghost button，不干擾閱讀）。

#### A.4.2 標記流程

```
學生點擊「標記不準確」
  → 彈出 modal，選填原因（必選其一）：
      A. 定義有誤
      B. 範例不符科目
      C. 練習題答案錯誤
      D. 與節點名稱無關
      E. 其他（自由填寫，限 100 字）
  → 送出後：
      ① 該鷹架對此學生隱藏（不影響其他學生），改顯示「已回報，感謝回饋」
      ② 寫入 scaffold_review_queue 表（欄位：scaffold_id / reporter_user_id / reason_code / note / created_at）
      ③ 該鷹架 trust_level 暫降至 PENDING_REVIEW
      ④ 若同一鷹架收到 ≥ 3 份不同用戶回報：自動對所有用戶隱藏，進入人工審核優先佇列
```

#### A.4.3 人工審核佇列（平台管理後台）

- 路徑：平台後台 → 內容審核 → AI 補洞鷹架審核佇列
- 每筆顯示：節點名稱、鷹架三段內容、信心分數、回報數、回報原因分布
- 操作：核准（trust_level → HUMAN_VERIFIED）/ 退回修改（由內容編輯重寫）/ 刪除
- SLA：有 ≥ 3 份回報的鷹架，48 小時內必須有人工決策

### A.5 風險紅線與 Fail-Safe

| 紅線場景 | Fail-Safe 機制 |
|---------|---------------|
| 佐證題 < 3 題 | 強制不生成，顯示「尚無足夠考古題支撐此節點的 AI 補洞」灰底提示 |
| 信心分數 < 31 | 不顯示鷹架內容，只顯示「AI 信心不足以提供有效補洞」 |
| LLM 回傳內容含外部 URL（幻覺型引用）| pipeline 後處理 regex 過濾，含 URL 的鷹架退回重生成，連續失敗 3 次則不生成 |
| 生成內容與節點名稱 cosine 相似度 < 0.55 | 視為幻覺偏離，自動退回，記錄 `generation_failure_reason = 'semantic_drift'` |
| 生成速度過慢（P95 > 30 秒）| 非同步排隊，學生當下看到「AI 補洞準備中，預計 5 分鐘後可見」而非 loading spinner |

### A.6 與既有「正式教材鷹架」差異對照表

| 面向 | 正式教材鷹架 | AI 補洞鷹架 |
|------|------------|------------|
| 來源 | 教師上傳 PDF / 影片，K-06 模板解析 | 考古題 retrieval，K-ORPHAN-01 模板 |
| trust_level | HUMAN_VERIFIED / SYSTEM_GENERATED | AI_INFERRED（新值，需 migration） |
| 邊框顏色 | 無特殊邊框（或綠色 ✓ 已審核）| amber（#F59E0B） |
| 學分計算權重 | 1.0×（完整計入 mastery progress） | 0.6×（降權，鼓勵繼續找正式教材）|
| 計入科目完成度 | 是（分母與分子都算）| 分母算，分子算 0.6 倍 |
| 顯示浮水印 | 否 | 是（常駐，不可關閉）|
| SM-2 排程 | 正常排程 | 排程間隔縮短 20%（督促學生補正式教材）|
| 可被標記不準確 | 否（已通過人工審核）| 是 |
| 生命週期 | 持久（除非資源刪除）| 若科目後來補進正式鷹架且覆蓋同節點 → 自動退場，系統通知學生 |

## 區塊 B — #6 完成度框架設計規範

### B.1 語言框架轉換：從「警告」到「解鎖」

**設計理念**：Dweck（2006）的成長型思維理論指出，固定型語言（「你缺少」「你遺漏」）觸發逃避動機；成長型語言（「尚未解鎖」「等待挑戰」）觸發趨近動機。語言本身即是干預工具。

#### B.1.1 文案改寫對照表（至少 8 條）

| 所在頁面 / 元件 | 現有文案 | 改寫後文案 | 改寫原則 |
|--------------|--------|----------|---------| 
| 知識心智圖節點 tooltip | ⚠️ 此節點尚無學習資源 | 📍 此關卡尚未解鎖（點此啟動 AI 補洞）| 行動導向，即時可行 |
| coverage-explained 頁標題 | 5-15% 覆蓋率漏洞 | 你已解鎖 {N}% 的知識版圖 | 正向框架先行 |
| coverage-explained 頁清單 | 9 個遺漏風險 | 9 個待解鎖關卡（預計難度：中 / 高）| 難度標記取代「風險」 |
| 個人儀表板弱點提示 | ⚠️ 5 個遺漏節點需補強 | 📍 5 個關卡等你挑戰 | 中性激勵語氣 |
| 個人儀表板完成度 | 覆蓋率：42% | 已解鎖：42%　　距甜蜜點還剩 43% | 錨定甜蜜點，給進度感 |
| 錯題複習頁空態 | 無錯題紀錄 | 目前沒有待修煉的題目，繼續保持！| 空態正向化 |
| 訂閱升級引導 | 免費版功能受限，升級以解除限制 | 升級後解鎖完整知識版圖 + AI 教練補洞 | 利益語言取代限制語言 |
| AI 補洞鷹架進入點 | 此節點無教材（AI 可嘗試生成）| ✨ AI 正在為你打造此關卡的學習鷹架 | 進行式，強調個人化 |
| 節點詳情頁 mastery = 0 | 尚未學習 | 準備出發 | 起跑感，非缺失感 |
| 心智圖全覽低覆蓋提示 | 您的學習地圖有大量空白區域 | 你的知識版圖正在成長中，繼續探索！| 動態感，非靜態缺陷感 |

### B.2 進度條算法

#### B.2.1 數學定義

完成度算法採三層加權：

```
科目完成度分數 S = Σ(節點權重 w_i × 節點 mastery 值 m_i) / Σ(節點權重 w_i)

其中：
  節點權重 w_i 由以下三個因素決定：
    w_i = 出題頻率權重 × 深度層級權重 × 覆蓋狀態調整

  出題頻率權重：
    考古題命中 ≥ 5 次 → 3.0
    考古題命中 2–4 次 → 2.0
    考古題命中 1 次   → 1.5
    考古題命中 0 次   → 1.0（仍計入分母，分子 mastery 通常也低）

  深度層級權重：
    depth = 1（chapter）→ 0.5（抽象層，學生難以直接練習，降權）
    depth = 2（section）→ 1.0（主力學習單元，標準權重）
    depth = 3（leaf）   → 1.2（最細粒度，考試最常直接命中）

  覆蓋狀態調整（針對 AI 補洞鷹架的 mastery 降權）：
    若節點 mastery 來自 AI 補洞鷹架練習題（非正式教材）：
      m_i_adjusted = m_i × 0.6
    否則：
      m_i_adjusted = m_i（原值）

  節點 mastery 值 m_i：
    0.0 = 未接觸
    0.5 = 曾答題但正確率 < 60%
    1.0 = 正確率 ≥ 60%（SM-2 間隔 ≥ 4 天）
    1.5 = 正確率 ≥ 85%（SM-2 間隔 ≥ 14 天，長期記憶確立）
```

#### B.2.2 分母選擇原則

| 計算對象 | 分母構成 | 適用場景 |
|---------|--------|--------|
| 甜蜜點進度條（主要顯示）| 僅含出題頻率 ≥ 1 次的節點 | 個人儀表板、學習儀錶板 |
| 全覆蓋進度條（次要顯示）| 所有 depth=2 節點 | coverage-explained 頁誠實揭露 |
| 考試衝刺模式進度條 | 前 30% 高頻考點節點 | 考試日 ≤ 14 天時自動切換顯示 |

**設計理由**：Karpicke & Roediger（2008）的間隔測試研究指出，學習資源有限時，高頻考點的優先練習比全面覆蓋帶來更高的實際考試成績提升。分母設計必須反映這一學習效益邏輯。

### B.3 徽章里程碑系統

| 解鎖條件（甜蜜點進度條）| 徽章名稱 | 解鎖文案 | 心理意義 |
|----------------------|--------|--------|--------|
| 首次完成任一節點（mastery ≥ 0.5）| 啟程者 | 知識之旅正式開始！| 降低第一步心理門檻 |
| 甜蜜點進度 ≥ 25% | 探索者 | 你已踏入這片知識版圖的第一個象限！| 標記初期進展，防中途放棄 |
| 甜蜜點進度 ≥ 50% | 建設者 | 過半關卡已解鎖，你正在這個領域站穩腳跟 | 中點成就感，提升後半段動力 |
| 甜蜜點進度 ≥ 85% | 甜蜜點達陣者 | 你已到達最高效益區間！繼續保持 or 轉攻模擬試卷 | 核心里程碑，85% 是效益最大點 |
| 甜蜜點進度 = 100% | 高頻王者 | 所有高頻考點制霸！建議轉往全題型模擬 | 強調下一步（模擬試卷）而非停在這 |
| 全覆蓋進度 = 100% | 知識完整者 | 每個知識節點都已接觸，是真正的全覆蓋學習者 | 稀有成就，誠實標明「含低頻考點」|

**設計理由**：85% 為甜蜜點的根據是 Bjork（1994）的 desirable difficulty 理論與 Dunning-Kruger 效應的交叉點——過低覆蓋率導致考試信心崩潰，過度追求 100% 帶來邊際效益遞減且觸發過度自信偏誤（Dunning & Kruger, 1999）。

### B.4 邊際效益遞減教育時機

系統應在以下條件同時滿足時，**主動**提示學生「策略轉換」而非繼續追 100%：

#### B.4.1 觸發條件（AND 關係）

1. 甜蜜點進度 ≥ 85%
2. 距離考試日期 ≤ 14 天（學生有填寫考試日期）
3. 全覆蓋進度 < 100%（代表仍有節點未接觸）
4. 用戶當前行為是「反覆練習已熟悉節點」（同節點 SM-2 間隔 ≥ 7 天仍在練習）

#### B.4.2 介入方式

```
系統提示卡（非 modal，不強制關閉）：

「你已解鎖 87% 的高頻考點！距考試還有 12 天，
 AI 建議：把剩餘時間投入模擬機考 + 錯題複習，
 效益 > 追求剩下 13% 的低頻考點。
 [切換到模擬機考]　[繼續補全覆蓋]（我有充裕時間）」
```

#### B.4.3 不介入的情境

- 學生明確點擊「我有充裕時間」：此提示本次考試週期不再出現
- 距考試 ≥ 30 天：時間充裕，鼓勵全覆蓋
- 學生是 B2B 機構帳號且機構設定「要求全覆蓋考核」：尊重機構設定，不顯示策略轉換提示

### B.5 反 Anti-Pattern 紅線

以下設計明確禁止，避免遊戲化讓學習行為失真：

| Anti-Pattern | 症狀 | 禁止設計 | 正確替代 |
|-------------|------|--------|--------|
| 徽章蒐集癖 | 學生只為解鎖徽章，不管 mastery 紅燈 | 禁止「今日登入即獲徽章」、「連續登入徽章」等無學習行為的獎勵 | 所有徽章必須綁定 mastery 指標 |
| 假進度感 | 進度條刷新但 mastery 未提升 | 禁止「讀完鷹架即算完成」計入進度 | 進度條只動於答題後 mastery 更新時 |
| 徽章遮蔽弱點 | mastery 紅燈節點被高進度遮蓋 | 禁止在儀表板以大尺寸徽章蓋住弱點警示 | 弱點雷達圖必須與徽章同層級顯示 |
| 速刷現象 | 學生亂點選項快速刷完題目只為提進度 | 禁止「作答即算 mastery 提升」，必須正確率 ≥ 60% 且 SM-2 確認 | mastery 更新邏輯由 SM-2 演算法決定，不可繞過 |
| 完成度通膨 | 平台為提升活躍度虛報完成度 | 禁止平台手動調整完成度數值 | 完成度計算邏輯須公開（coverage-explained 頁說明算法）|

### B.6 與信心度校準（Dashboard）整合點

| 整合點 | 說明 | 優先級 |
|-------|------|--------|
| 信心 vs 實力差距預警 | 若學生自評信心 ≥ 80% 但甜蜜點進度 < 50% → 儀表板紅燈標記「信心與覆蓋率落差過大」| P1 |
| 甜蜜點進度反映信心校準建議 | ≥ 85% 時儀表板主動建議「進行信心校準測驗確認實力」| P2 |
| 徽章不計入信心分數 | 信心校準結果純從答題表現計算，徽章數不影響任何信心指標 | 必要紅線 |
| 完成度框架作為信心校準 pre-step | 引導學生先提升完成度（≥ 60%）再做信心校準，避免樣本太少導致校準誤差大 | P2 |

## 區塊 C — #9 AI 教練回應 Orphan 設計規範

### C.1 對話啟動：蘇格拉底式提問 Prompt 模板

**設計理念**：蘇格拉底式提問（Socratic questioning）的有效性在於讓學習者從既有知識中主動建構理解，而非被動接收（Hmelo-Silver & Barrows, 2006; Karpicke, 2011）。AI 教練應扮演「引導者」而非「解釋者」。

#### C.1.1 啟動 Prompt 模板（AI 教練發出第一句話）

```
你好！我看到你正在探索「{node_name}」這個概念，
而目前這個節點還沒有完整教材。

讓我們一起用你已有的知識來思考看看：

在學習「{parent_node_name}」（{node_name} 的上層概念）時，
你印象中有沒有接觸過和「{node_name}」相關的部分？

不用擔心答錯，這是探索的開始。
```

#### C.1.2 三個學科範例

**範例一：金融（不動產估價師）**
```
AI 教練：
你好！我看到你正在探索「大量估價法」這個概念，而目前這個節點還沒有完整教材。

讓我們一起用你已有的知識來思考看看：
在學習「不動產估價方法」（大量估價法的上層概念）時，
你印象中有沒有接觸過「比較法」或「收益法」？

這些方法有什麼共同的出發點？試著說說你的想法。
```

**範例二：iPAS（AI 應用規劃師）**
```
AI 教練：
你好！我看到你正在探索「RAG 架構設計原則」這個概念，這裡還沒有完整教材。

來試著從你學過的「向量資料庫」出發：
你記得向量資料庫解決的是什麼問題嗎？
如果 LLM 要「查詢外部知識」，你覺得這個查詢流程大概是什麼樣的？
```

**範例三：高普考（行政學）**
```
AI 教練：
你好！我看到你正在探索「網絡治理理論」這個概念，這裡的教材還在準備中。

讓我從你可能熟悉的角度切入：
你學過「科層制」和「市場機制」嗎？
如果這兩個極端都有缺點，「網絡」在中間扮演什麼角色？
試著猜猜看。
```

### C.2 Context 注入規格

AI 教練在接到「用戶點擊 orphan 節點」觸發時，系統應向 LLM 注入以下 context：

```json
{
  "trigger_type": "orphan_node",
  "node": {
    "id": "{uuid}",
    "name": "{節點名稱}",
    "depth": 2,
    "parent_name": "{上層 chapter 名稱}",
    "subject_name": "{科目名稱}"
  },
  "neighbor_nodes": [
    {
      "name": "{top-1 cosine 鄰居節點名}",
      "similarity": 0.78,
      "student_mastery": 0.5
    },
    {
      "name": "{top-2 cosine 鄰居節點名}",
      "similarity": 0.72,
      "student_mastery": 1.0
    },
    {
      "name": "{top-3 cosine 鄰居節點名}",
      "similarity": 0.65,
      "student_mastery": 0.0
    }
  ],
  "exam_frequency": {
    "total_questions_in_subject": 120,
    "questions_hitting_this_node": 4,
    "frequency_percentile": 65
  },
  "student_context": {
    "mastery_score": 0.0,
    "last_attempted_at": null,
    "error_rate_on_similar_nodes": 0.55,
    "days_to_exam": 21,
    "subscription_tier": "PRO_199"
  },
  "ai_scaffold_available": false,
  "ai_scaffold_confidence": null
}
```

**Context 使用原則**：
- `neighbor_nodes`：AI 教練用 top-3 鄰居節點引導「從已知到未知」的 Ausubel 連結
- `exam_frequency`：若頻率百分位 ≥ 60%，AI 教練應明確告知「這是高頻考點，值得花時間」
- `student_mastery`（鄰居節點的）：若鄰居 mastery = 0，AI 教練先引導回鄰居節點，而非深入 orphan

### C.3 學生回答後評分機制

#### C.3.1 評分架構

蘇格拉底對話的回答不能用標準客觀題評分。採用以下三層評估：

| 評估維度 | 評分依據 | 評分主體 |
|---------|--------|--------|
| 概念接觸度（0 / 0.5 / 1）| 學生回答是否提及相關領域概念（模糊或精確）| LLM 評分 |
| 推理連結度（0 / 0.5 / 1）| 學生是否嘗試建立因果或類比關係 | LLM 評分 |
| 主動性（0 / 0.5）| 學生回答長度 ≥ 20 字且非隨機輸入 | 規則判斷 |

單輪對話最高分 = 2.5。

#### C.3.2 是否計入 Mastery

**計入 mastery，但採降權係數**：

```
蘇格拉底對話 mastery 貢獻 = 對話最終得分 / 2.5 × 0.4

說明：
  0.4 係數（vs 正式答題的 1.0）反映：
  (1) 評分主觀，LLM 評分有誤差
  (2) 知識建構不如答題提取（retrieval）效果穩定
  (3) 鼓勵學生在獲得 AI 對話 mastery 後繼續答正式考古題

觸發 mastery 更新的條件：
  - 對話至少進行 3 輪（問答各算一輪）
  - 至少 2 輪中學生回答得分 ≥ 1.5 / 2.5
  - 否則：記錄對話紀錄但 mastery 值不更新
```

#### C.3.3 SM-2 排程整合

- 蘇格拉底對話觸發 mastery 更新後，以 E-Factor = 1.8（低於正式答題的 2.5）寫入 SM-2
- 意味對話後的複習間隔比答題後短 → 督促學生繼續補正式教材

### C.4 對話結束條件

#### C.4.1 自然結束（正向）

- 條件：學生在 3-5 輪內展現足夠的概念連結，AI 評分 ≥ 1.5/2.5
- AI 教練收尾語：
  ```
  你的思考方向很到位！「{概念}」的核心邏輯你已經抓到了。
  接下來建議：
  [1] 試試這個節點相關的考古題（{N} 道）
  [2] 查看 AI 為你準備的補洞鷹架（如可用）
  ```

#### C.4.2 轉介外部資源

當以下任一條件觸發，AI 教練主動建議外部資源：

| 觸發條件 | 轉介動作 |
|---------|--------|
| 對話 5 輪後學生回答概念接觸度仍 = 0 | 建議「可先看《{科目建議用書}》第 {X} 章」（書目資料由平台管理員預設）|
| 學生明確表達「我完全不懂這塊」| 建議 Coursera / 官方考綱指定教材 |
| 節點屬於法律 / 法規類（需精確定義，不適合 Socratic 發散）| 直接告知「此類概念需要精確法條，建議查閱{法規名稱}第{X}條」|

#### C.4.3 建議改答考古題的時機

- 對話累計 ≥ 3 輪且學生回答得分 ≥ 1.0/2.5（有基礎但不紮實）：AI 教練插入「我出一道考古題測試看看」
- 注意：此時切換為正常答題流程（非蘇格拉底式），答題結果計正常 mastery 權重

#### C.4.4 強制結束（非正向）

- 對話超過 8 輪：系統自動結束，顯示「今日探索到這裡！這個概念我們改天繼續」，寫入對話紀錄
- 學生 3 分鐘無回應：對話暫停，下次進入同節點自動接續對話（保留上下文）

### C.5 與既有 AI 教練（答錯題詳解）的差異與重用

| 面向 | 既有 AI 教練（錯題詳解）| Orphan AI 教練（蘇格拉底對話）|
|------|---------------------|---------------------------|
| 觸發時機 | 學生答錯後 | 學生點擊 orphan 節點 |
| 對話目標 | 解釋為什麼這題錯 | 引導學生從已知建構未知 |
| 對話長度 | 1-2 輪（解釋為主）| 3-8 輪（探索為主）|
| Prompt 風格 | 分析型、解釋型 | 提問型、引導型（Socratic）|
| Context 注入 | 該題題目 + 選項 + 正確答案 + 學生選項 | 節點資訊 + 鄰居節點 + 出題頻率 + 學生 mastery |
| Mastery 影響 | 不直接影響 mastery，屬複習輔助 | 降權計入 mastery（0.4 係數）|

**可重用元件**：
- LLM 客戶端封裝（`ai_coach_service.py` 中的 `_call_llm` / `_stream_response`）
- 對話紀錄資料表（`ai_coach_conversations`，若結構相容則共用，否則新表 `orphan_coach_conversations`）
- 前端對話 UI（`AiCoachPanel.tsx`，傳入 `mode="socratic"` prop 以切換對話風格）

**必須重新設計**：
- System Prompt：錯題詳解的系統提示強調「解釋邏輯」，Orphan 教練必須強調「不給答案、只給引導」，System Prompt 不可共用
- Context 注入格式：兩者 context 結構完全不同（見 C.2 規格），不可共用同一 context builder
- 評分機制：錯題詳解不評分；Orphan 教練需 LLM 評分學生回答品質

### C.6 LLM 選擇：Sonnet vs Haiku 成本權衡

#### C.6.1 Token 估算（單次完整對話）

```
System Prompt：約 800 tokens
Context 注入（C.2 規格）：約 400 tokens
對話輪次（平均 5 輪，每輪 user 150 + AI 200）：約 1750 tokens
收尾語 + 建議：約 150 tokens

單次對話總 token 估算：
  Input tokens：800 + 400 + (5 × 150) = 1950 tokens
  Output tokens：(5 × 200) + 150 = 1150 tokens

費用估算（2026-05 定價）：
  Claude Haiku 3.5：Input $0.8/M + Output $4/M
    = (1950 × 0.8 + 1150 × 4) / 1,000,000
    = (1560 + 4600) / 1,000,000 ≈ USD $0.006 / 對話

  Claude Sonnet 4.5：Input $3/M + Output $15/M
    = (1950 × 3 + 1150 × 15) / 1,000,000
    = (5850 + 17250) / 1,000,000 ≈ USD $0.023 / 對話

Sonnet 比 Haiku 貴約 3.8×。
```

#### C.6.2 選擇建議：分層策略

| 訂閱方案 | 建議 LLM | 理由 |
|---------|--------|------|
| FREE | Haiku 3.5 | 成本控制，每月上限 5 次 orphan 對話 |
| PRO_199 | Haiku 3.5（預設）/ 可升 Sonnet（用戶設定）| 平衡成本與品質 |
| PRO_PLUS_399 | Sonnet 4.5 | 蘇格拉底引導品質要求高，值得用 Sonnet |
| ULTRA_1599 | Sonnet 4.5 + 無次數限制 | 高端方案，全面品質 |

**教育顧問意見**：Orphan 節點的蘇格拉底對話是「最難」的 AI 教練任務——學生對節點完全不了解，AI 必須既不洩露答案，又能引導出有意義的回答。這個任務 Haiku 在複雜法規 / iPAS 深度技術問題上的表現明顯落後。建議 PRO+ 以上方案統一採用 Sonnet，作為差異化功能亮點。

## 驗收標準（Acceptance Criteria）

### 機制 #2 AI 自動補洞鷹架

**AC-2.1**（觸發條件）
```
Given 一個 orphan 節點，其出題頻率 ≥ 1 次、佐證題精確命中 ≥ 3 題
When pipeline 執行 AI 補洞生成
Then 系統生成一份含「定義 / 範例 / 練習題」三段的鷹架，
     信心分數 > 30，amber 邊框顯示，浮水印常駐
```

**AC-2.2**（Fail-Safe）
```
Given 一個 orphan 節點，佐證題精確命中 < 3 題
When 系統嘗試觸發 AI 補洞生成
Then 不生成鷹架，顯示「佐證題不足，無法自動補洞」灰底提示
     scaffold_review_queue 不新增記錄
```

**AC-2.3**（標記不準確流程）
```
Given 一份 AI 補洞鷹架已顯示給學生
When 學生點擊「標記不準確」並選擇原因後送出
Then 該鷹架對此學生隱藏
     scaffold_review_queue 新增一筆記錄（含 reporter_user_id / reason_code）
     鷹架 trust_level 更新為 PENDING_REVIEW（若已有 3 份回報）
```

**AC-2.4**（mastery 降權）
```
Given 學生透過 AI 補洞鷹架的練習題答對
When mastery 計算更新
Then 此次 mastery 貢獻 = 正式教材練習題的 0.6 倍
     科目完成度進度條同步更新（含 0.6 降權算法）
```

**AC-2.5**（退場機制）
```
Given 一個節點原為 orphan 並已有 AI 補洞鷹架
When 教師上傳正式教材，解析後產生覆蓋同節點的正式鷹架
Then AI 補洞鷹架自動標記為 SUPERSEDED（不刪除，保留歷史）
     學生下次進入該節點看到正式鷹架，並收到「此節點已補充完整教材」通知
```

### 機制 #6 完成度框架

**AC-6.1**（文案一致性）
```
Given 任一「⚠️ 遺漏」相關字眼在系統所有頁面
When 完成度框架上線
Then 全站不再出現「遺漏」「空白」「警告」等負向文案（B.1.1 對照表全部替換）
     QA 須以 grep 確認前端 codebase 無殘留
```

**AC-6.2**（進度條算法）
```
Given 一個科目有 20 個 depth=2 節點，其中 5 個已 mastery=1.0（正式題），3 個 mastery=0.6（AI 補洞題 × 0.6 降權），12 個 mastery=0
When 系統計算甜蜜點完成度（分母：有出題頻率的節點，假設 15 個）
Then 進度條顯示值 = (5 × 1.0 × 各自權重 + 3 × 0.6 × 各自權重) / (15 個節點加權總和)
     計算誤差 < 0.5%（避免浮點問題）
```

**AC-6.3**（邊際效益遞減介入）
```
Given 學生甜蜜點進度 ≥ 85%，且距考試日 ≤ 14 天
When 學生在儀表板或心智圖頁停留
Then 系統顯示策略轉換提示卡（非 modal）
     提示卡包含「切換到模擬機考」與「繼續補全覆蓋」兩個 CTA
```

**AC-6.4**（徽章與 mastery 綁定）
```
Given 學生未完成任何答題，只閱讀了鷹架內容
When 系統計算徽章解鎖條件
Then 不觸發任何徽章（徽章解鎖嚴格要求 mastery 更新，閱讀不算）
```

### 機制 #9 AI 教練回應 Orphan

**AC-9.1**（對話啟動）
```
Given 學生點擊一個 orphan 節點，節點有有效的 context（鄰居節點 ≥ 1）
When AI 教練對話啟動
Then 第一句話符合 C.1.1 模板格式（含節點名稱 + 上層節點名稱）
     不直接提供節點定義或答案
```

**AC-9.2**（Mastery 計入條件）
```
Given 學生與 AI 教練完成 3 輪以上對話，至少 2 輪評分 ≥ 1.5/2.5
When 對話結束
Then mastery 更新，貢獻值 = 最終分 / 2.5 × 0.4
     SM-2 以 E-Factor = 1.8 排程複習
```

**AC-9.3**（轉介外部資源）
```
Given 對話進行 5 輪後，學生概念接觸度仍 = 0
When 系統評估對話狀態
Then AI 教練主動建議外部資源（平台設定的書目或官方考綱）
     對話不強制結束，學生仍可繼續
```

**AC-9.4**（System Prompt 隔離）
```
Given Orphan 教練與錯題詳解教練使用同一 LLM 服務
When 兩個教練各自被觸發
Then 兩者使用完全不同的 System Prompt（不共用任何段落）
     Orphan 教練的 System Prompt 不含「解釋」「給答案」「正確答案是」等字眼
```

## 三個機制的優先順序建議

### 建議順序：#6 → #2 → #9

#### 第一優先：#6 完成度框架

**理由**：

1. **零技術依賴**：文案改寫與進度條算法調整不依賴 scaffold_node_links（migration 090）完成，可立即執行。
2. **覆蓋面最廣**：影響所有用戶、所有頁面，是「平台感知轉型」而非單點功能。學習焦慮是整體問題，語言框架是最快的系統性干預。
3. **正向基底建立**：先把平台語言從「警告模式」轉為「解鎖模式」，才能讓後續的 AI 補洞鷹架和 AI 教練對話在正確的情緒基調上運作。在焦慮氛圍中推出 amber 邊框 AI 鷹架，可能加劇而非緩解焦慮。
4. **學習科學支撐最強**：Dweck 成長型思維（2006）有大量實證研究，文案改寫的 ROI 高、風險低。

**預計工期**：1 週（前端文案替換 + 算法調整 + 徽章 UI）

#### 第二優先：#2 AI 自動補洞鷹架

**理由**：

1. **直接解決 CEO 顧慮**：「學生看到遺漏地圖卻找不到教材」，#2 提供的 amber 邊框鷹架是最直接的教材補位機制。
2. **依賴 Sprint 10 完成**：需要 `scaffold_node_links`（D1）和 `trust_level` 新值（D2），等 Sprint 10 schema 上線後即可啟動。
3. **Bjork desirable difficulty 支撐**：retrieval-first 三段模板（定義 → 範例 → 練習題）已對齊科學學習法，不是粗糙的「文字補充」。
4. **風險可控**：Fail-Safe 機制（信心分數門檻、浮水印、標記不準確）已充分設計，教育品質有保底。

**預計工期**：2-3 週（pipeline 整合 + 信心分數 + 標記流程 + UI）

#### 第三優先：#9 AI 教練回應 Orphan

**理由**：

1. **最高成本與複雜度**：蘇格拉底對話需要最長的工程開發周期（新 context 架構、新評分機制、System Prompt 設計迭代），且成本最高（Sonnet per 對話）。
2. **效果需要基底**：若學生對節點完全陌生（#6 尚未建立正向框架）且沒有任何鷹架可參照（#2 尚未上線），蘇格拉底對話的引導效果有限——Hmelo-Silver & Barrows（2006）指出 PBL / Socratic 的前提是學生有「足夠的先備知識碎片」可被引導連結。
3. **差異化價值最高**：但這也代表它是三個機制中最有機會創造「WOW」時刻的功能，適合作為 PRO+ 方案的旗艦功能在 #6 和 #2 打好基礎後隆重推出。

**預計工期**：3-4 週（含測試與 Prompt 迭代）

### 優先順序摘要

| 排序 | 機制 | 時機 | 核心理由 |
|------|------|------|--------|
| 1 | #6 完成度框架 | 立即（本 Sprint）| 零依賴、覆蓋最廣、建立情緒基底 |
| 2 | #2 AI 補洞鷹架 | Sprint 10 後 | 直接補教材缺口、依賴已排程 |
| 3 | #9 Orphan AI 教練 | Sprint 11-12 | 最高複雜度，需 #6 + #2 先上線 |
