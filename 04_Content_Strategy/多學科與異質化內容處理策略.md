# 多學科與異質化內容處理策略

因應平台轉型為「純工具導向」，使用者上傳的內容將包含極大的差異性（如：數學公式推導、英文閱讀測驗、程式碼講義、法規條文）。為了確保 AI 能夠產出高品質的考題，必須導入「動態分類與適配」機制。

## 1. 使用者引導與意圖宣告 (User-Guided Context)
在檔案上傳階段，除了讓使用者拖曳檔案外，增加極簡的選項讓使用者宣告資料屬性（可選填，也可交由 AI 自動判斷）：
- **內容領域**：理工數學 (STEM) / 語文檢定 / 專業證照法規 / 一般內部訓練
- **內容型態**：純文字講義 / 包含大量圖表公式 / 歷屆考古題

## 2. AI 自動分類與預處理 (Pre-processing Routing)
當檔案進入後端 Pipeline：
1. **取樣分析 (Sampling)**：抽取 PDF 前 3 頁或目錄，送入輕量級 LLM (如 GPT-4o-mini 或 Claude 3 Haiku)。
2. **路由分發 (Router)**：根據取樣結果，將文件派發給不同的「專家解析引擎」。

## 3. 領域專家引擎設計 (Domain-Specific Pipelines)

### A. 語文類 (例如：英文考題、多益)
- **切塊策略 (Chunking)**：以「段落 (Paragraph)」或「單篇文章」為單位切塊，確保閱讀測驗的上下文完整。
- **Prompt 策略**：要求 LLM 著重於單字替換、文法糾錯、段落主旨擷取 (Main idea)。可以自動生成「克漏字 (Cloze test)」或「閱讀測驗題組 (Reading Comprehension)」。

### B. 理工數學類 (例如：微積分、工程數學)
- **視覺化解析 (Vision Parsing)**：傳統的 PDF 文字擷取程式會把數學符號 (Sigma, 積分號) 變成亂碼。此類文件必須透過 GPT-4o Vision 或類似的多模態模型，「整頁截圖」當成圖片送交分析，轉譯為 LaTeX 語法。
- **Prompt 策略**：著重於「計算步驟推導」、「公式應用」。生成的考題必須使用 Markdown 的 LaTeX 數學語法包覆（例如 `$E=mc^2$`），前端則引入 `MathJax` 或 `KaTeX` 進行渲染。

### C. 程式語言與 IT 類 (例如：AWS、Python 講義)
- **切塊策略**：以 Markdown 的 Code Block 或技術標題層級為分割點，切忌攔腰截斷一段程式碼。
- **Prompt 策略**：生成「找 Bug」、「給定 Input 預測 Output」或「架構情境題」。

### D. 法規與死記硬背類 (例如：金融證照、不動產經紀人)
- **切塊策略**：利用法條的前綴符號（如：第 X 條、第 Y 項）進行嚴格的章節切塊。
- **Prompt 策略**：生成「情境應用題」（某人犯了什麼法）或是「細節陷阱題」（罰鍰數字、年限的易混淆選項）。

## 4. 系統容錯機制 (Fallback Mechanism)
- 如果 AI 判斷這是一份「完全雜亂、品質過差的掃描檔」，系統應在 30 秒內提早中斷解析，並發出友善提示請使用者提供更清晰的檔案或文字檔，避免浪費無用的 Token 成本。
