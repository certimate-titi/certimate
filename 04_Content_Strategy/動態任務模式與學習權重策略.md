# 動態任務模式與學習權重策略

採用全自定義開發的演算法與資料權重架構，將系統設計為類似「即時作業系統（RTOS）」的概念：根據當前的「任務模式（Mode）」動態分配使用者的學習精力給不同的題型與任務。

以下是針對不同時間軸設計的系統架構與權重演算邏輯：

---

## 1. 資料核心：資料庫 Schema 設計
每一條知識點（Item）不只是問答，必須帶有「權重屬性」以供後台演算法調度。

```sql
CREATE TABLE flashcards (
    id INTEGER PRIMARY KEY,
    content TEXT,           -- 題目與答案 (JSON 格式)
    category TEXT,          -- 類別 (例如：程式語言, 外語, 專業知識)
    source_type TEXT,       -- 來源類型 [UNSEEN (未看過), WRONG (錯誤), QUERY (查詢), LINK (關聯)]
    created_at DATETIME,
    last_reviewed DATETIME,
    success_count INTEGER DEFAULT 0,
    fail_count INTEGER DEFAULT 0,
    ease_factor REAL DEFAULT 2.5, -- 簡單度因子 (應用於間隔重複演算法)
    tags TEXT               -- 關聯標籤
);
```

---

## 2. 三種「任務模式」的權重演算邏輯
系統提供一個 `Mode` 參數，根據選擇的模式，動態產出每一次的「考題比例」，達到最優化的學習成效。

### A. 短期衝刺模式 (Sprint Mode: 7-14 天)
* **情境：** 短期內面臨測驗、證照考試或專案死線。
* **策略：** **放棄長久記憶，追求「短期識別度」。** 高頻率刷錯題與未考資料。
* **比例建議：**
    * **曾經錯誤 (50%)：** 高頻率重現，直到連續多次正確。
    * **未曾考過 (40%)：** 快速覆蓋尚未閱讀或練習過的內容。
    * **查詢資料 (10%)：** 僅限關鍵術語的加強。
    * **遺忘邊緣 (0%)：** 暫時忽略，將精力集中於短期內會考的高報酬率題目。

### B. 正常準備模式 (Standard Mode: 1-3 個月)
* **情境：** 規律的課程學習或中長期的檢定準備。
* **策略：** **動態位移。** 依照學習時間軸的推移進行權重轉移。
* **比例建議：** 採用「開拓期 → 鞏固期 → 衝刺期」的自動權重。
    * 初期：加重新資料的佔比 (約 60%)。
    * 後期：進入遺忘邊緣的複習題佔比提高 (約 50%)，以確保知識穩固。

### C. 長久學習模式 (Mastery Mode: 6 個月以上)
* **情境：** 職涯核心技能與專業語言的長期內化。
* **策略：** **極大化「抗遺忘」。** 減少新資料推進速度，並著重跨領域概念的關聯。
* **比例建議：**
    * **遺忘邊緣 (70%)：** 嚴格遵守間隔重複 (Spaced Repetition) 演算法。
    * **跨章節關聯題 (20%)：** 系統隨機挑選兩個相異標籤強迫寫出關聯性。
    * **新資料 (10%)：** 緩慢推進，確保穩紮穩打。

## 3. 實際應用與排程策略：動態單一模式 + 跨科目並行

在實際應用上，系統採用類似作業系統的排程概念來管理使用者的學習精力：

1. **針對單一科目（時間軸上的單一動態模式）**：
   對於特定的單一備考科目，在同一個時間點**只會處於一種任務模式**。系統會根據使用者設定的「預計考試日期」，在背景自動隨著時間推移切換模式（例如從 Mastery $\rightarrow$ Standard $\rightarrow$ Sprint）。這是一條單向演化路徑，免除使用者手動切換的選擇障礙。
2. **針對全站學習（跨科目多任務並行）**：
   使用者可同時準備多個科目，不同的科目宛如不同的執行緒，各自處於專屬的進度與模式。儀表板即扮演著中央工作排程器（Task Scheduler）的角色。
   - **範例**：下週即將考試的證照處於 🔥 **Sprint 模式**；三個月後的外語檢定處於 🏃 **Standard 模式**；做為長期職涯培養的程式語言則處於 🌳 **Mastery 模式**。
3. **大腦精力的池化分配（Energy Pooling）**：
   系統會根據各科目當前所處任務模式的緊急度，自動分配今日的總學習心力。例如，若今日可學習 180 分鐘，系統可自動優先將 120 分鐘分配給 Sprint 模式的高頻錯題，剩餘時間再分派給其他模式，達成最高效的大腦算力調度。

## 4. 邏輯引擎虛擬碼 (Logic Engine)
利用結構化與模式匹配的設計原則處理動態權重邏輯，以下為通用的邏輯演算法概念：

```javascript
// 任務模式定義
const StudyMode = {
    SPRINT: 'Sprint',      // 短期衝刺
    STANDARD: 'Standard',  // 正常準備
    MASTERY: 'Mastery'     // 長久學習
};

// 根據模式與進度取得配題權重
function getQuizConfig(mode, progressPercent) {
    switch (mode) {
        case StudyMode.SPRINT:
            return { unseenRatio: 0.4, wrongRatio: 0.5, retentionRatio: 0.0, linkRatio: 0.1 };
            
        case StudyMode.STANDARD:
            // 根據進度百分比動態調整
            if (progressPercent < 0.3) {
                // 前期：開拓期 (著重新資料)
                return { unseenRatio: 0.6, wrongRatio: 0.3, retentionRatio: 0.1, linkRatio: 0.0 };
            } else if (progressPercent < 0.7) {
                // 中期：鞏固期 (均衡發展)
                return { unseenRatio: 0.3, wrongRatio: 0.3, retentionRatio: 0.3, linkRatio: 0.1 };
            } else {
                // 後期：衝刺準備 (著重复習與錯題)
                return { unseenRatio: 0.1, wrongRatio: 0.4, retentionRatio: 0.4, linkRatio: 0.1 };
            }
            
        case StudyMode.MASTERY:
            return { unseenRatio: 0.1, wrongRatio: 0.1, retentionRatio: 0.6, linkRatio: 0.2 };
            
        default:
            throw new Error("未知的學習模式");
    }
}
```

## 5. 系統設計的關鍵細節

1. **結合能力雷達的雙重篩選 (Dual-Funnel Filtering)：**
   在產生每日考題時，除了依靠「動態任務模式」決定各類型題目的權重比例（如錯題 50% / 新題 40%）外，系統還會提取使用者的「能力分佈雷達圖 (Skill Radar)」數據進行二級篩選。例如在挑選該 40% 的新題區間時，考題產生引擎會優先抽取雷達圖中最弱的知識領域，達成「大方向依循時間軸，小細節瞄準個人弱點」的精準打擊與考題設計。
2. **「查詢資料」的自動轉化：**
   可整合快速查詢工具或系統捷徑 API。當使用者檢索特定術語時，能一鍵將該段內容送入資料庫中，並自動標記為 `source_type: QUERY`，以便後續無縫轉化為考題。
3. **加入「壓力因子」：**
   在「短期衝刺」模式下，系統應限制每題的回答時間。若作答超時，系統即自動判定為 `WRONG`，強制該題目進入高頻複習循環。
4. **關聯性檢索 (The Linker)：**
   利用資料庫的全文檢索 (Full-Text Search) 功能，尋找標籤相似但來源截然不同的卡片，強制將它們組合在一起進行「對比式考題」，藉此強化長久學習模式下的跨域知識連結能力。

## 6. 實作路徑建議

* **第一步：** 實作核心演算法引擎，使其能讀取資料庫，並根據使用者選定的任務模式 (Sprint / Standard / Mastery) 動態篩選出今日應練習的題目清單與對應權重。
* **第二步：** 實作狀態更新機制的邏輯 (`update_stats`)，當使用者回答完畢後，精準更新該題目的最後複習時間 (`last_reviewed`)、難易度指標 (`ease_factor`) 以及連續成功與失敗的次數。
* **第三步：** 串接前端介面 (Web UI 或應用程式介面)，將後端運算完成的動態分發題目以流暢、直覺的互動體驗呈現給使用者。
