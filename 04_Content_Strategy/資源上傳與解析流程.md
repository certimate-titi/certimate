# 資源上傳與解析流程

## 1. 資源輸入 (Resource Input)

本平台支援雙軌資源匯入模式，極大化降低使用者的冷啟動門檻：

### A. 實體檔案上傳 (File Upload)

- **支援格式**：PDF、Markdown、TXT、**Image (PNG/JPG/JPEG/WebP，觸發 Vision OCR)**。
- **大小限制**：免費版 **10MB**，Pro 版 **100MB**。
- **機制**：提供明確的進度條 (Polling / WebSocket)，因 PDF 的版面解析與切割較為耗時。

### B. YouTube 影片連結解析 (Video URL via MCP)

- **運作原理**：使用者無需準備講義，直接貼上 YouTube 教學影片網址。
- **技術實作 (MCP 架構)**：
  - 後端不直接處理爬蟲，而是透過 **Model Context Protocol (MCP)** 呼叫獨立部署的 `youtube-transcript-mcp-server`。
  - MCP Server 負責抓取影片的 CC 字幕 (Transcript) 並清洗時間軸標籤，將純文字逐字稿回傳給主系統。
- **長度限制**：免費版僅支援長度小於 **30 分鐘** 且有內建字幕的影片；Pro 版支援大時數課程 (如 10小時 Bootcamp) 甚至未來可調用 Whisper 進行無字幕語音轉檔。

## 2. 後端與 AI 解析 (Backend Pipeline)

1. **觸發解析任務**：
   - 實體檔案：成功傳至 GCS 後觸發 Webhook 或 Pub/Sub。
   - YouTube：MCP Server 成功回傳逐字稿純文字。
2. **版權與異常審查 (Copyright & Policy Check) 【新增防護點】**：
   - 在正式進入資源密集的 LLM 運算前，快速掃描前 2 頁或逐字稿中是否密集出現 "授權嚴禁轉載", "版權所有", "Confidential" 等高風險關鍵字。
   - 若觸發警報，系統自動中斷流程，回傳錯誤訊息至前端要求使用者再次宣告獨立授權。
3. **文字過濾與清洗**：
   - PDF：移除不必要的頁首頁尾、浮水印，確保文本純淨。
   - YouTube 逐字稿：利用 LLM 快速進行「口語贅字濾除」與「標點符號重建」，以利後續理解。
4. **智慧切塊 (Semantic Chunking)**：
   - 不只是單純按字數切，盡量以 Markdown Header (H1, H2) 或邏輯段落切分，保持知識點的完整性。
5. **知識結構擷取與心智圖生成 (Mind Map Generation)**：
   - 向 LLM 請求為整份文件/影片腳本建立階層式的知識節點 (Knowledge Nodes, 如章節、核心概念)。
   - 將這些節點轉換為 JSON 格式的心智圖結構 (支援父子節點關聯)。
   - 每個心智圖節點會「綁定」對應的 Document Chunks 或 YouTube 時間軸，實現點擊節點即可查閱原始說明的互動。
6. **Embedding 與雙軌儲存入庫 (Dual-Storage Strategy)**：
   - 解析流程完成後，只保留兩層，並立即刪除原始檔：
     - **Layer 1 - GCS Markdown 庫 (Warm Storage)**：永久保存解析後正規化的 `.md` 純文字檔（每份資源對應一個 `.md`）。這是防幻覺溯源、Re-embedding 、混合搜尋與未來資料匯出的「真理之源」（詳細設計請參閱 `01_Management/資料儲存與向量化架構決策.md`）。
     - **Layer 2 - pgvector 向量索引 (Hot Index)**：將 `.md` 切塊後的 Chunks 轉為高維度 Embedding 陣列，寫入 Cloud SQL (PostgreSQL) 的 pgvector 擴充。此層為語意搜尋引擎，並與 pg tsvector 全文搜尋共同形成 **Hybrid Search** 混合配題能力。
   - **原始檔（PDF / 圖片 / 錄音）的生命週期**：
     - 解析狀態確認為 `COMPLETED` 後 → 立即從 GCS **永久刪除**原始檔，節省儲存空間。
     - 解析狀態為 `FAILED` → **保留**原始檔於 GCS，讓使用者可在資源庫管理頁面點擊「重新解析」重試，直到成功後才刪除。
