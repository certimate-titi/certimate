# 資安防護與隱私規範 (Security & Privacy Standards)

## 📌 核心防護原則

CertiMate 處理大量的使用者學習資源與個人數據，確保資料的 **機密性 (Confidentiality)**、**完整性 (Integrity)** 與 **可用性 (Availability)** 是系統設計的首要任務。我們採取「縱深防禦 (Defense in Depth)」策略，從多個層次構建安全防線。

---

## 🔐 1. 身分驗證與存取控制 (Identity & Access)

### A. 強化驗證機制

- **OAuth 2.0 / OpenID Connect**：優先採用 Google SSO，利用成熟雲端廠商的安全架構減少帳密外洩風險。
- **JWT 安全管理**：
  - 使用 `HttpOnly` 與 `Secure` 標記的 Cookies 儲存 Tokens，防止 XSS 攻擊竊取對話。
  - 實作短效 Access Token 與長效 Refresh Token 機制。
- **多重因素驗證 (MFA)**：針對 B2B 教育機構管理者 (Admin) 與內部維運工程師，強制啟動 MFA。

### B. 嚴格的權限模型 (RBAC & RLS)

- **最小權限原則 (PoLP)**：每個 API 與服務帳戶僅擁有完成其職責所需的最小權限。
- **行級安全性 (Row Level Security, RLS)**：在 PostgreSQL 層級實作 RLS，確保 A 使用者的 API 請求絕不可能查詢到 B 使用者的資料，即便 API 邏輯出現 Bug。

---

## 🛡️ 2. 基礎設施與網路安全 (Infrastructure)

### A. 網路邊界防護

- **HTTPS 全程加密**：強制使用 TLS 1.3 加密，關閉所有不安全的連線協議。
- **API 閘道 (Cloud API Gateway)**：
  - **流量清洗**：過濾惡意偵測請求與 DDoS 攻擊。
  - **速率限制 (Rate Limiting)**：透過 Redis 實作針對特定 IP 與 UserID 的頻率管控，防止 API 被自動化腳本榨乾。
- **WAF (Web Application Firewall)**：阻斷 OWASP Top 10 常見攻擊（如 SQL 注入、跨站腳本 XSS ）。

### B. 私有網路運算

- **VPC 隔離**：將資料庫、快取與後端 AI Worker 置於不對外開放的 VPC 私有子網內。
- **邊緣安全 (App Check)**：利用 Firebase App Check 確保只有來自官方網站的請求能存取後端 API，阻擋羊毛黨直接呼叫 API 介面。

---

## 💾 3. 資料安全與隱私加密 (Data Protection)

### A. 靜態與動態加密

- **靜態加密 (Encryption at Rest)**：所有儲存於 Cloud SQL、Pinecone 與 Google Cloud Storage 的資料一律使用 AES-256 加密。
- **簽署連結 (Signed URLs)**：用戶上傳的 PDF 與圖片檔案不會公開讀取權限，僅在讀取時產生具有時效性 (如 5 分鐘) 的私密連結供前端下載。

### B. 資料清理與脫敏

- **敏感資訊過濾**：在將文本送入 AI 模型前，實作初步的 PII (個人識別資訊) 檢測與去除。
- **資料刪除權**：使用者執行「刪除帳號」後，系統將觸發級聯刪除 (Cascading Delete)，同步清除資料庫記錄、向量索引與 GCS 中的實體檔案。

---

## 🤖 4. AI 模型安全 (LLM Security)

### A. 防範提示注入 (Prompt Injection)

- **輸入驗證與過濾**：對輸入的資源內容進行格式檢測與長度限制。
- **指令隔離**：在 System Prompt 採用嚴格的區隔符號，明確劃分「任務指令」與「使用者內容」，防止使用者內容篡改 AI 指令。

### B. 資料隱私承諾 (Nontraining)

- **不被訓練原則**：透過企業級 OpenRouter / Azure OpenAI / Google Vertex AI 合約，確保使用者上傳的機密講義 **絕不會被用於基礎模型的二次訓練 (Fine-tuning)**。

---

## 🔍 5. 合規與審計 (Compliance & Audit)

### A. 日誌記錄

- **安全審計日誌 (Audit Logs)**：詳盡記錄所有涉及權限變更、訂閱狀態修改與大量資料匯出的操作人員與時間。
- **異常監控 (Sentry/Cloud Logging)**：當系統偵測到異常集中的失敗登入或頻繁的向量檢索失敗，將立即發送警報至維運團隊 Slack/Discord。

### B. 防禦性開發

- 定期進行手動程式碼審查 (Code Review) 關注安全隱患。
- 計畫上線前進行弱點掃描 (Vulnerability Scanning)。
