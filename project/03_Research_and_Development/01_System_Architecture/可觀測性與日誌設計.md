## 1. 設計目標

CertiMate 的核心業務邏輯是**跨三個 Cloud Run 服務的非同步流程**：

```
Frontend → Main API → Cloud Pub/Sub → AI Worker → YouTube MCP
```

當使用者上傳 PDF 或 YouTube 連結後，這條鏈路可能耗時 5~60 秒，橫跨兩個服務與一個訊息佇列。傳統的 `print()` / `console.log()` 無法讓我們在出問題時快速追蹤「某一個 taskId 到底卡在哪一步、哪個服務丟出了 Error、整條任務花了多久」。

**目標：** 在所有服務導入一致的 JSON 結構化日誌，讓每一行 log 都帶有 `taskId`，可在 Google Cloud Logs Explorer 中用單一查詢語句還原任何一個任務從上傳到考卷生成的**完整時間軸**。

## 2. Log Envelope JSON Schema（所有服務共用）

每個服務一律將以下格式的 JSON 物件印到 **stdout**。Cloud Run 的 log agent 會自動將 stdout 轉送到 Google Cloud Logging，並依照 Google 特殊欄位命名慣例解析 `severity`、`trace`、`timestamp`。

```json
{
  "severity": "INFO",
  "timestamp": "2026-03-15T08:23:41.123456Z",
  "service": "main-api",
  "version": "1.4.2",
  "taskId": "task_abc123def456",
  "userId": "firebase_uid_xyz789",
  "documentId": "doc_uuid_here",
  "examId": null,
  "logging.googleapis.com/trace": "projects/certimate-prod/traces/4bf92f3577b34da6a3ce929d0e0e4736",
  "logging.googleapis.com/spanId": "00f067aa0ba902b7",
  "logging.googleapis.com/trace_sampled": true,
  "message": "GCS upload completed",
  "data": {
    "gcs_path": "users/xyz789/task_abc123/lecture.pdf",
    "file_size_bytes": 2048576,
    "duration_ms": 342
  },
  "error": null
}
```

### 欄位規則

| 欄位 | 類型 | 必填 | 說明 |
| :--- | :--- | :---: | :--- |
| `severity` | string | ✓ | Google 格式：`DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL` |
| `timestamp` | string (ISO 8601 UTC) | ✓ | 微秒精度；Cloud Logging 用此欄位排序時間軸 |
| `service` | string | ✓ | 固定值：`"main-api"` / `"ai-worker"` / `"youtube-mcp"` |
| `version` | string | ✓ | 來自環境變數 `SERVICE_VERSION`，方便對照部署版本 |
| `taskId` | string \| null | ✓ | 核心關聯欄位；僅 health-check log 可為 `null` |
| `userId` | string \| null | ✓ | Firebase UID；背景排程任務可為 `null` |
| `documentId` | string \| null | 建議 | 已知時填入 |
| `examId` | string \| null | 建議 | Exam 建立後填入 |
| `logging.googleapis.com/trace` | string | 建議 | 完整格式：`projects/{project}/traces/{traceId}`；填入才能顯示「View Trace」連結 |
| `logging.googleapis.com/spanId` | string | 建議 | Hex span ID |
| `logging.googleapis.com/trace_sampled` | boolean | 建議 | 固定填 `true` |
| `message` | string | ✓ | **靜態字串**，不內嵌動態值（動態值放 `data`），確保 Logs Explorer filter 可靠 |
| `data` | object | ✓ | 結構化 payload；**嚴禁**放入使用者上傳的文字內容（遵循 [[資安防護與隱私規範]] PII 規定） |
| `error` | object \| null | 條件必填 | `severity` 為 `ERROR` / `CRITICAL` 時必填 |

### Error 子物件格式

```json
"error": {
  "type": "EmbeddingAPIError",
  "message": "OpenRouter returned 429 after 3 retries",
  "stack": "Traceback (most recent call last):\n  ...",
  "code": 429,
  "retries_attempted": 3
}
```

> **⚠️ 重要：** Exception stack trace 必須 escape 為單行（`\n` 轉義），不能讓多行字串破壞 JSON 格式。下方各語言的 library 均已自動處理。

## 3. Node.js 實作 — Main API（pino）

### 為何選 pino

- 原生輸出 JSON，寫到 stdout，無需額外 transport
- 支援 `AsyncLocalStorage` child logger，讓 `taskId` 在整個 request lifecycle 自動傳遞
- 效能約為 Winston 的 5 倍，適合高頻率請求的 API 服務

### 安裝

```bash
npm install pino pino-http
```

### `src/lib/logger.ts` — 初始化（含 GCP formatter）

```typescript
import pino from 'pino'

const PROJECT_ID = process.env.GCP_PROJECT_ID ?? 'certimate-prod'

export const logger = pino({
  formatters: {
    level(label: string) {
      const map: Record<string, string> = {
        trace: 'DEBUG', debug: 'DEBUG', info: 'INFO',
        warn: 'WARNING', error: 'ERROR', fatal: 'CRITICAL',
      }
      return { severity: map[label] ?? 'DEFAULT' }
    },
    // 移除 Cloud Run 上多餘的 pid / hostname 欄位
    bindings() { return {} },
    log(obj: Record<string, unknown>) {
      const out = { ...obj }
      if (obj.traceId) {
        out['logging.googleapis.com/trace'] =
          `projects/${PROJECT_ID}/traces/${obj.traceId}`
        out['logging.googleapis.com/spanId'] = obj.spanId
        out['logging.googleapis.com/trace_sampled'] = true
      }
      return out
    },
  },
  timestamp: pino.stdTimeFunctions.isoTime,
  base: {
    service: 'main-api',
    version: process.env.SERVICE_VERSION ?? 'unknown',
  },
  // 自動將 Error 物件序列化為單行 JSON（含 stack trace escape）
  serializers: {
    err: pino.stdSerializers.err,
    error: pino.stdSerializers.err,
  },
})
```

### `src/lib/context.ts` — AsyncLocalStorage（讓 taskId 自動傳遞）

```typescript
import { AsyncLocalStorage } from 'async_hooks'

export interface RequestContext {
  taskId: string | null
  userId: string | null
  documentId: string | null
  traceId: string | null
  spanId: string | null
}

export const requestContext = new AsyncLocalStorage<RequestContext>()

export function getContext(): RequestContext {
  return requestContext.getStore() ?? {
    taskId: null, userId: null, documentId: null,
    traceId: null, spanId: null,
  }
}
```

### `src/lib/logger.ts`（擴充）— Contextual Logger Factory

```typescript
import { getContext } from './context'

// 在 request 內任意位置呼叫，自動帶入當前 AsyncLocalStorage 的 context
export function getLogger() {
  return logger.child(getContext())
}
```

### `src/middleware/logging.middleware.ts` — Express Middleware

```typescript
import { Request, Response, NextFunction } from 'express'
import { requestContext, RequestContext } from '../lib/context'
import { logger } from '../lib/logger'
import admin from 'firebase-admin'

function parseTraceHeader(header?: string) {
  if (!header) return { traceId: null, spanId: null }
  const match = header.match(/^([a-f0-9]+)\/(\d+)/)
  if (!match) return { traceId: null, spanId: null }
  return {
    traceId: match[1],
    spanId: Number(match[2]).toString(16).padStart(16, '0'),
  }
}

export async function loggingMiddleware(
  req: Request, res: Response, next: NextFunction,
) {
  const { traceId, spanId } = parseTraceHeader(
    req.headers['x-cloud-trace-context'] as string,
  )

  let userId: string | null = null
  const authHeader = req.headers.authorization
  if (authHeader?.startsWith('Bearer ')) {
    try {
      const decoded = await admin.auth().verifyIdToken(authHeader.slice(7), true)
      userId = decoded.uid
    } catch { /* token 驗證失敗由 auth middleware 處理，此處僅略過 */ }
  }

  const ctx: RequestContext = { taskId: null, userId, documentId: null, traceId, spanId }

  requestContext.run(ctx, () => {
    const log = logger.child(ctx)
    log.info({ data: { method: req.method, path: req.path } }, 'Request received')

    const start = Date.now()
    res.on('finish', () => {
      const finalCtx = requestContext.getStore() ?? ctx
      logger.child(finalCtx).info(
        { data: { method: req.method, path: req.path, status: res.statusCode, duration_ms: Date.now() - start } },
        'Request completed',
      )
    })
    next()
  })
}
```

## 4. Python 實作 — AI Worker（structlog）

### 為何選 structlog

- `bind()` API 讓 `taskId` 在整個 worker invocation 自動附加在所有 log 上
- `JSONRenderer` 輸出 flat 單行 JSON，符合 Cloud Logging 要求
- Hook stdlib `logging`，讓 FastAPI / uvicorn / SQLAlchemy 也輸出結構化 JSON

### 安裝

```bash
pip install structlog>=24.0.0
```

### `app/core/logging.py` — 初始化

```python
import logging, os, sys, time
from datetime import datetime, timezone
import structlog

GCP_PROJECT_ID = os.environ.get("GCP_PROJECT_ID", "certimate-prod")
SERVICE_NAME = "ai-worker"
SERVICE_VERSION = os.environ.get("SERVICE_VERSION", "unknown")


def add_gcp_fields(logger, method, event_dict: dict) -> dict:
    """Structlog processor：將欄位對應到 Google Cloud Logging 規範。"""
    severity_map = {
        "debug": "DEBUG", "info": "INFO",
        "warning": "WARNING", "error": "ERROR", "critical": "CRITICAL",
    }
    level = event_dict.pop("level", "info")
    event_dict["severity"] = severity_map.get(level, "DEFAULT")
    event_dict["message"] = event_dict.pop("event", "")

    trace_id = event_dict.get("traceId")
    span_id = event_dict.get("spanId")
    if trace_id:
        event_dict["logging.googleapis.com/trace"] = (
            f"projects/{GCP_PROJECT_ID}/traces/{trace_id}"
        )
    if span_id:
        event_dict["logging.googleapis.com/spanId"] = span_id
        event_dict["logging.googleapis.com/trace_sampled"] = True

    event_dict.setdefault("service", SERVICE_NAME)
    event_dict.setdefault("version", SERVICE_VERSION)
    event_dict["timestamp"] = datetime.now(timezone.utc).isoformat(timespec="microseconds")
    return event_dict


def configure_logging():
    """在 main.py 啟動時呼叫一次。"""
    shared_processors = [
        structlog.stdlib.add_log_level,
        structlog.stdlib.add_logger_name,
        add_gcp_fields,
    ]

    structlog.configure(
        processors=[
            *shared_processors,
            structlog.processors.dict_tracebacks,       # stack → 單行 JSON
            structlog.processors.JSONRenderer(sort_keys=False),
        ],
        wrapper_class=structlog.make_filtering_bound_logger(logging.DEBUG),
        context_class=dict,
        logger_factory=structlog.PrintLoggerFactory(file=sys.stdout),
        cache_logger_on_first_use=True,
    )

    # Hook stdlib logging（uvicorn / FastAPI / SQLAlchemy 也走 structlog）
    logging.basicConfig(format="%(message)s", stream=sys.stdout, level=logging.DEBUG)
    for handler in logging.root.handlers:
        handler.setFormatter(structlog.stdlib.ProcessorFormatter(
            processors=[
                structlog.stdlib.ProcessorFormatter.remove_processors_meta,
                *shared_processors,
                structlog.processors.JSONRenderer(sort_keys=False),
            ]
        ))
```

### `app/workers/resource_worker.py` — Pub/Sub 消費端

```python
import base64, json, time
import structlog
from app.core.logging import configure_logging

configure_logging()
base_log = structlog.get_logger()


def handle_push_request(request_body: dict):
    message = request_body.get("message", {})
    attributes = message.get("attributes", {})

    # ① 立即 bind taskId（從 attributes，不需解碼 body）
    #   即使後續 body parse 失敗，error log 也帶有 taskId
    log = base_log.bind(
        taskId=attributes.get("taskId"),
        userId=attributes.get("userId"),
        documentId=attributes.get("documentId"),
    )

    log.info("Pub/Sub message received",
             data={"message_id": message.get("messageId"),
                   "publish_time": message.get("publishTime")})

    # ② 解碼 body
    try:
        body = json.loads(base64.b64decode(message["data"]).decode("utf-8"))
    except Exception as exc:
        log.error("Failed to decode Pub/Sub message body",
                  error={"type": type(exc).__name__, "message": str(exc)})
        return {"status": "ack"}  # ack 避免無限重試

    # ③ 執行 pipeline
    try:
        _run_pipeline(log, body)
    except Exception as exc:
        log.error("Pipeline failed with unhandled exception",
                  error={"type": type(exc).__name__, "message": str(exc)},
                  exc_info=True)
        update_task_status(body.get("taskId"), "FAILED")
        raise


def _run_pipeline(log, body: dict):
    start = time.monotonic()

    log.info("Chunking started", data={"document_id": body["documentId"]})
    chunks = chunk_document(body["documentId"])
    log.info("Chunking completed",
             data={"chunk_count": len(chunks), "duration_ms": _ms(start)})

    t = time.monotonic()
    embeddings = embed_chunks(chunks)
    log.info("Embedding completed",
             data={"chunk_count": len(chunks), "model": embeddings.model_used,
                   "duration_ms": _ms(t)})

    t = time.monotonic()
    upsert_to_pinecone(body["documentId"], chunks, embeddings)
    log.info("Vector DB upsert completed",
             data={"chunk_count": len(chunks), "duration_ms": _ms(t)})

    t = time.monotonic()
    exam = generate_exam(body["documentId"], body["userId"])
    log.info("Exam generated",
             data={"exam_id": exam.id, "question_count": len(exam.questions),
                   "model_used": exam.model_used, "duration_ms": _ms(t)})

    update_task_status(body["taskId"], "COMPLETED", exam_id=exam.id)
    push_sse_notification(body["userId"], body["taskId"], exam.id)
    log.info("Task completed",
             data={"exam_id": exam.id, "total_duration_ms": _ms(start)})


def _ms(since: float) -> int:
    return int((time.monotonic() - since) * 1000)
```

## 5. taskId 跨服務傳遞 — Pub/Sub Attributes

`taskId` 必須同時放入 Pub/Sub 訊息的 **body** 和 **attributes** 兩個管道：

| 傳遞路徑 | 方式 |
| :--- | :--- |
| Main API → Pub/Sub | `attributes: { taskId, userId, documentId }` + body JSON |
| Pub/Sub → AI Worker | AI Worker 從 `message.attributes.taskId` 提取（不需解碼 body） |
| AI Worker → YouTube MCP | HTTP query string：`GET /transcript?videoId=xyz&taskId=task_abc123` |

**為何 attributes 和 body 都放？**
1. Pub/Sub subscription filter 可按 attribute 路由，不需反序列化 body
2. Body parse 失敗時，error log 仍可從 attributes 取到 `taskId`
3. Dead-letter queue 的死信訊息也能被追蹤

## 7. Severity 等級規範

| Level | 典型事件 |
| :--- | :--- |
| **DEBUG** | Embedding 每批進度、Redis cache lookup、DB status 更新、SSE push 送出、YouTube 逐字稿分頁進度 |
| **INFO** | Request received/completed、GCS upload completed、Task record created、Pub/Sub published、Chunking/Embedding/Exam generated/Task completed |
| **WARNING** | OpenRouter 429 retry、Pinecone partial failure retry、任務超過 SLA 門檻（如 > 60s）、Pub/Sub redelivery（attempt > 1）、配額使用量 > 80%、YouTube fallback to auto-captions |
| **ERROR** | GCS/Pub/Sub/DB 操作失敗、Pipeline unhandled exception、Pub/Sub message 缺少 `taskId`、全部 retry 耗盡、Exam 生成結果題數為零 |
| **CRITICAL** | 服務啟動失敗（無法連 Cloud SQL / Pub/Sub）、Pinecone client init 失敗、OOM crash（Cloud Run 自動記錄） |

## 10. 須注意的陷阱

1. **AI Worker 第一行 log 就必須帶 `taskId`** — 從 Pub/Sub attributes 提取，早於 body 解碼。即使 body parse 失敗，error log 也有 `taskId` 可查。

2. **絕不 log 使用者上傳的文字內容** — `data` 物件只記 chunk count、file size、GCS path、UUID。文字內容屬於使用者個資，不得出現在 log 中（[[資安防護與隱私規範]]）。

3. **Exception stack 必須 escape 成單行** — pino 的 `serializers.err` 和 structlog 的 `dict_tracebacks` 會自動處理。不要直接用 Python `logging.exception()` 搭配 raw handler，會讓 stack trace 橫跨多行，破壞 Cloud Logging 的 JSON 解析。

4. **`message` 欄位要靜態** — 寫 `"GCS upload completed"` 而非 `"GCS upload of ${filename} completed"`。動態值一律放 `data`。靜態 message 才能在 Logs Explorer 中用 `jsonPayload.message="..."` 精確 filter。

5. **Node.js `AsyncLocalStorage` 在 callback 中可能斷鏈** — `setTimeout` / `setImmediate` 內的 callback 有時無法繼承 AsyncLocalStorage context。若某個 log 顯示 `taskId: null`，確認是否在 async chain 之外。修法：在 request 開始時 `const ctx = getContext()` 捕獲後手動傳入該 callback。
