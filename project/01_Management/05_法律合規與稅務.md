# TiTi 法律合規與稅務規範

**建立日期**：2026-04-01
**文件目的**：整合 TiTi 平台（AI 驅動證照考試備考 SaaS）之法律聲明、版權防護、營業登記、稅務義務、B2B 合規與未成年保護等規範，作為團隊法律遵循的單一參考文件。

---

## Part 1：服務條款與隱私權

### 1.1 核心法律風險

TiTi 結合「生成式 AI」與「使用者自建內容 (UGC)」，營運上面臨三大核心法律風險：

1. **使用者上傳侵權內容（著作權風險）**：使用者可能上傳受版權保護的電子書、官方教材、補習班講義。
2. **AI 幻覺與不正確內容（過失免責）**：AI 可能產生錯誤的考題解答或解釋，導致考生在真實考試中落榜。
3. **無間斷服務保證（第三方依賴問題）**：高度依賴 OpenAI / Anthropic / Google 等第三方 LLM，上游服務中斷時平台無法運作。

### 1.2 服務條款 (Terms of Service) 必備免責聲明

使用者註冊時必須勾選同意的「服務條款」中，應明文涵蓋以下條款：

#### 1.2.1 AI 內容免責聲明 (AI Content Disclaimer)

- **非專業保證（No Guarantee of Accuracy）**：明確標明平台產生之測驗考題、知識節點、AI 教練的對話「皆由人工智慧模型自動生成，系統無法 100% 保證內容之正確性、完整性與時效性」。
- **考試結果免責**：明確聲明「本平台提供的模擬考試成績僅供參考，**平台與營運方對使用者的實際考試、證照取得結果不負任何直接或間接之擔保責任**」。如因信賴本系統解答而導致落榜、考試失利，不構成退款、賠償之理由。

#### 1.2.2 使用者內容上傳與著作權規範 (UGC & Copyright Policy)

- **合法授權宣誓**：使用者上傳之任何文檔（PDF、影像）、影音連結（YouTube 網址），皆須自行保證擁有合法使用權利或已取得版權方授權，得用以作為個人學習之用途。
- **安全港灣條款 (Safe Harbor / DMCA)**：平台做為網路服務提供者 (ISP)，不事先審核使用者上傳之檔案。若第三方版權方提出侵權申訴，平台有權（在不經通知使用者的情況下）徑行刪除或隱藏該爭議資源，且不承擔任何連帶賠償責任。
- **禁止公開分享侵權內容**：即便系統支援筆記分享或題庫共享，使用者亦不得將包含未授權版權內容的測驗庫公開至社群，否則平台有權立刻停權。
- **TIPO（智慧財產局）侵權處理**：如收到台灣 TIPO 或其他國際版權機關之正式通知函，平台將依據通知-取下 (Notice and Takedown) 程序，於 72 小時內處理。

#### 1.2.3 服務中斷與第三方服務依賴 (Service Interruption)

- **不保證中斷**：本平台使用第三方 AI 模型服務與雲端基礎設施。如遇不可抗力（如上游模型 API 故障、海底電纜斷線、大型網路攻擊），導致功能（包含但不限於文件解析、AI 教練問答）暫時無法使用，平台將盡力修復，但不對暫時性服務中斷衍生的損失提供賠償。
- **合規使用第三方模型**：使用者同意在上傳文件及發送對話時，相關資料將可能傳輸至 OpenAI / Anthropic / Google 以進行處理。

### 1.3 隱私權政策 (Privacy Policy) 重點宣告

針對個資與隱私保護（對齊台灣《個人資料保護法》(PDPA) 及歐盟 GDPR）：

#### 1.3.1 AI 模型訓練排除宣告

必須清楚告知使用者：「**本平台承諾，使用者上傳之私人學習資料、文件與測驗記錄，不會被用來作為平台訓練自家 AI 模型的語料庫**。所有資料僅透過安全的 API 傳送給第三方 LLM（並要求第三方不作為訓練資料）進行您專屬的任務處理。」

> 此宣告能大幅降低企業/教育機構用戶的防備心，為 B2B 拓展鋪路。

#### 1.3.2 個資保留與刪除權 (Right to be Forgotten)

- 明確告知於發生退費、刪除帳號時，使用者有權要求清空所有使用紀錄與個人資訊，系統將於 **30 日內**從資料庫中徹底銷毀（包含向量資料庫中的 Embedding 特徵）。
- **PDPA 第 3 條**：當事人得向資料蒐集者請求刪除其個人資料。
- **GDPR 第 17 條**：資料主體之被遺忘權 (Right to Erasure)。

#### 1.3.3 快取合規

- Redis 快取等效能加速工具中的關聯資料，必須在後端刪除邏輯中同步執行 `del` 清除指令。
- 所有 Redis Key 應設定 **TTL（Time-to-Live）自動過期機制**，以確保暫存資料不會無限期留存，落實隱私權保護並避免法律爭議。

## Part 2：版權防護與免責聲明

### 2.1 三振退場機制 (Three-Strike Policy)

為加強平台自律，若使用者的公開分享庫遭版權方檢舉達 **三次（3 Strikes）**，系統將：
1. 永久封禁該帳號
2. 不予退還任何已預繳之訂閱費用
3. 透過數位浮水印反解析鎖定洩漏源頭

### 2.2 系統主動式版權防禦機制 (Active Copyright Defense)

#### 2.2.1 上傳前沿版權掃描 (Copyright Pre-Filter)

在文件進入 LLM 解析前，系統會快速掃描 Metadata 與純文字內容。若密集偵測到以下強烈版權宣告字眼（且佔比超過安全閾值），系統將自動暫停解析並彈出警告：

- "Copyright", "All Rights Reserved"
- "版權所有翻印必究", "Do Not Distribute"

要求使用者再次確認擁有個人授權，或直接拒絕高風險文件。

#### 2.2.2 數位隱形浮水印 (Invisible Digital Watermarking)

針對由系統產生的 PDF 考卷匯出檔、心智圖或可下載的靜態資源，系統將在底層（或以肉眼無法察覺的微小像素）嵌入該使用者的 **UID 與生成時間截記**。若未來網路上出現未經授權大規模流傳的 TiTi 題庫，營運方可透過反解析浮水印精準鎖定洩漏源頭並執行帳號封鎖。

### 2.3 UI 介面上的免責提示設計 (UX/UI Implementation)

| 位置 | 設計 | 文案 |
|------|------|------|
| AI 教練聊天視窗底部 | 固定灰色小字 | 「AI 生成內容僅供參考，請隨時自行查證重要資訊。」 |
| 上傳按鈕區 / AI 聊天輸入框邊緣 | 淡灰色 `#9CA3AF`、字號 10px、對比度極低 | 「*點擊上傳即視為您保證擁有此檔案的合法使用權，並同意不公開散佈。*」 |
| 測驗結果單元下方 | 小字提示 | 「本模擬考試結果僅反映當前熟悉度，並不保證實測通過率。」 |

> **設計理念**：採用「執行動作即同意 (Clickwrap / Browsewrap)」的網路慣例取代強制勾選框，確保使用者沉浸在學習心流中不被打斷，同時完成法律免責。

## Part 3：營業登記與稅務義務

### 3.1 台灣營業登記門檻

在台灣經營 SaaS 軟體服務收費，必須遵守國稅局針對銷售勞務的銷售額門檻規定：

| 階段 | 月營收門檻 | 登記要求 | 發票要求 | 營業稅率 |
|------|-----------|---------|---------|---------|
| 初期驗證 | < **50,000 TWD** | 無須辦理營業登記（稅籍登記） | 無須開立統一發票 | 0%（併入個人綜合所得稅） |
| 成長期 | **50,000 ~ 200,000 TWD** | **必須**向國稅局辦理「稅籍登記」 | 可申請「免用統一發票」，國稅局按季寄發稅單 | **1%** |
| 擴展期 / B2B | >= **200,000 TWD** | **必須**正式設立「行號」或「有限公司」 | **必須**正式開立「統一發票」 | **5%** |

> **重要**：有辦理稅籍登記的網路銷售，網頁下方必須清楚揭露「營業名稱」與「統一編號」。

### 3.2 金流收費管道

#### 3.2.1 綠界科技 (ECPay) / 藍新科技 (NewebPay) — 台灣在地初期首選

- **身分要求**：支援「個人戶」申請，初期不需公司登記，只需個人身分證與銀行帳戶。
- **額度限制**：綠界個人會員每月信用卡收款上限為 **300,000 TWD**（超過需轉公司戶）。
- **收費方式**：支援單次刷卡、ATM、超商代碼。支援「信用卡定期定額」（適合 199 TWD 訂閱制），但申請時可能需審查網站服務條款。
- **發票服務**：提供電子發票系統模組 (B2C/B2B)，未來營收達標需開發票時可直接啟用。

#### 3.2.2 Stripe — 開發體驗最佳，但在台灣有門檻

- **身分要求**：Stripe 官方尚未開放台灣實體營運（無法直接用台灣身分證及台灣銀行帳戶申請）。
- **解套方式**：
  - 線上開立「香港匯豐銀行 (One 帳戶)」後，申請「香港 Stripe 個人帳戶」，過程合法可遠端完成。
  - 透過 Stripe Atlas 於美國德拉瓦州設立 LLC 公司開通金流。
- **優缺點**：API 開發體驗極佳，完美支援 SaaS 訂閱、升降級與退費。缺點為除了基本手續費外，會有匯損與跨境結算手續費（綜合成本約比台灣本地金流高 **1.5% ~ 2.5%**）。

#### 3.2.3 LINE Pay

- **身分要求**：直接與 LINE Pay 官方簽約通常要求「公司登記/商業登記」核准函，個人開發者門檻高。
- **解套方式**：透過綠界或藍新作為第三方支付代收（在後台開啟 LINE Pay 結帳選項），個人戶也能間接提供 LINE Pay 付款方式。

## Part 4：B2B 合規與未成年保護

### 4.1 B2B 企業客戶附加法律條約

針對補習班、企業機構使用 TiTi 的 B2B 機構管理後台（Feature 10）：

#### 4.1.1 資料處理協議 (Data Processing Agreement, DPA)

- 機構做為「**資料控制者 (Data Controller)**」，TiTi 做為「**資料處理者 (Data Processor)**」，需明定雙方權責。
- **GDPR 第 28 條**：資料處理者須提供足夠保證，以確保處理符合本規則之要求並保護資料主體之權利。
- **PDPA 第 4 條**：受公務機關或非公務機關委託蒐集、處理或利用個人資料者，於本法適用範圍內，視同委託機關。

#### 4.1.2 DPA 必備條款

| 條款 | 內容 |
|------|------|
| 處理目的 | 僅限於提供 TiTi 平台服務之必要範圍 |
| 資料類型 | 學員姓名、Email、學習記錄、測驗成績 |
| 資料保留期限 | 合約終止後 90 日內完成刪除 |
| 次處理者 (Sub-processor) | 明列 GCP、OpenAI、Anthropic 等第三方服務 |
| 資料外洩通知 | 發現資料外洩後 72 小時內通知資料控制者 |
| 稽核權 | 機構有權對 TiTi 之資料處理進行稽核 |

### 4.2 PDPA x 未成年學生保護（B2B 教育情境）

當補習班或學校透過 TiTi B2B 方案將未成年學生（18 歲以下）匯入平台時，必須遵守以下規範：

#### 4.2.1 法定代理人同意機制

- **PDPA 第 7 條第 1 項**：蒐集非公務機關之個人資料，應有特定目的，並符合法定事由（如「經當事人書面同意」）。
- **針對未成年人**：依《民法》第 77 條，限制行為能力人（7~18 歲）之法律行為須得法定代理人同意。
- **實作要求**：B2B 合約中須明定，機構在匯入未成年學員之個人識別資料（姓名、Email）前，**必須已依法取得法定代理人之書面同意**。

#### 4.2.2 最小資料蒐集原則

- **PDPA 第 5 條**：個人資料之蒐集、處理或利用，應尊重當事人之權益，依誠實及信用方法為之，不得逾越特定目的之必要範圍。
- **GDPR 第 5 條第 1 項 (c)**：資料最小化原則 (Data Minimisation)。
- **實作要求**：未成年學生帳號僅蒐集學習所需之最低限度資料，不蒐集電話號碼、住址、身分證字號等非必要資訊。

#### 4.2.3 未成年人專屬保護措施

| 保護措施 | 說明 |
|---------|------|
| **社群功能限制** | 未成年學生帳號預設關閉社群分享、留言等互動功能，需由機構管理員手動開啟 |
| **AI 教練對話過濾** | 針對未成年帳號，AI 教練回覆增加安全過濾層，避免產生不適當內容 |
| **資料存取範圍** | 機構管理員僅能查閱其所屬學員之學習數據，不可跨機構存取 |
| **帳號生命週期** | 學員畢業或離開機構後，機構須通知 TiTi 停用該帳號；停用後 90 日自動刪除資料 |
| **隱私聲明簡化版** | 提供適合未成年人理解的簡化版隱私權說明（白話文、大字版） |

#### 4.2.4 機構端責任清單

機構（補習班/學校）簽署 B2B 合約時，須書面確認以下事項：

1. 已取得所有未成年學員之法定代理人書面同意，同意蒐集、處理及利用個人資料於 TiTi 平台。
2. 已將 TiTi 之隱私權政策（包含簡化版）提供予法定代理人閱覽。
3. 法定代理人有權隨時撤回同意，機構須於 **7 個工作日內**通知 TiTi 停用該學員帳號。
4. 機構須指派「**資料保護聯絡人**」，負責與 TiTi 溝通個資相關事宜。

## Part 5：階段行動計畫

將法律合規與稅務義務對齊 TiTi 產品開發的四階段 Roadmap：

### Phase 1：MVP（MRR < 50,000 TWD）

| 項目 | 行動 |
|------|------|
| **營運身分** | 個人 |
| **金流串接** | 申請「綠界科技 ECPay」個人會員 |
| **收費實作** | 串接單次刷卡（買點數）或綠界信用卡定期定額（199 TWD 訂閱） |
| **發票** | 暫不開立發票，於《收費與退費機制準則》中註明：現階段以「個人身分與電子收據」營運 |
| **服務條款** | 完成服務條款 (ToS) 與隱私權政策 (Privacy Policy) 初版，涵蓋 AI 免責、UGC 著作權、Safe Harbor |
| **版權防護** | 實作上傳前沿版權掃描 (Copyright Pre-Filter) |
| **UI 免責** | 所有 AI 生成頁面加入免責小字提示 |

### Phase 2：Beta（MRR 50,000 ~ 200,000 TWD）

| 項目 | 行動 |
|------|------|
| **營運身分** | 向國稅局辦理「稅籍登記」 |
| **稅務** | 申請「免用統一發票」，按季繳納 **1%** 營業稅 |
| **網頁揭露** | 網頁下方加入營業名稱與統一編號 |
| **版權防護** | 實作數位隱形浮水印 (Invisible Watermarking) + 三振退場機制 |
| **隱私權強化** | 實作帳號刪除流程（含向量資料庫 Embedding 清除 + Redis TTL 機制） |
| **TIPO 流程** | 建立 TIPO / DMCA 侵權通知處理 SOP（72 小時回應） |

### Phase 3：GTM（MRR >= 200,000 TWD，啟動 B2B）

| 項目 | 行動 |
|------|------|
| **營運身分** | 委託會計師設立「有限公司」，向國稅局申請電子發票字軌 |
| **稅務** | 正式開立統一發票，申報繳納 **5%** 營業稅 |
| **金流升級** | 綠界帳號由個人戶升級為「特約/特店（公司戶）」，串接綠界電子發票模組 |
| **發票自動化** | 全面實作 API 自動化開立電子發票並發送至使用者信箱，滿足 B2B 客戶報帳需求 |
| **B2B 合約** | 完成 DPA（資料處理協議）範本，涵蓋 PDPA 第 4 條 / GDPR 第 28 條 |
| **未成年保護** | 實作法定代理人同意機制、未成年帳號社群限制、AI 對話安全過濾 |
| **隱私權政策** | 更新隱私權政策，加入 B2B 資料處理、未成年保護專章 |

### Phase 4：Ecosystem（規模化擴展）

| 項目 | 行動 |
|------|------|
| **跨境合規** | 若拓展海外市場，評估 GDPR 完整合規（含 DPO 指派、跨境資料傳輸 SCCs） |
| **Stripe 評估** | 視國際市場需求，開通 Stripe 金流（香港帳戶或 Stripe Atlas LLC） |
| **資安認證** | 評估 ISO 27001 / SOC 2 Type II 認證，強化 B2B 企業客戶信任 |
| **法律顧問** | 聘請常駐法律顧問，定期審閱 ToS / Privacy Policy / DPA |
| **稽核機制** | 建立年度個資處理稽核流程，確保所有次處理者 (Sub-processors) 合規 |
