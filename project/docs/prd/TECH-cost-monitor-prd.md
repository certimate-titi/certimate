## 1. 背景與問題

CertiMate 使用三家 AI 供應商（Anthropic、Google Gemini、Voyage AI）與 GCP 基礎設施，目前**無任何成本可視化機制**。風險包括：

- Prompt injection、無限 retry 或程式 bug 可能導致單日燒掉數千美元（特別是 Voyage 無官方預算上限）
- 無法即時發現異常流量暴增
- 帳單到月底才知道，無法在事中干預
- 無法依成本趨勢調整定價策略與容量規劃

## 2. 目標與成功指標

### 2.1 商業目標
- **成本透明化**：Super Admin 可即時掌握每家供應商的當月金額
- **成本可控化**：預算門檻觸發後自動降級或停用，防止失控
- **合規稽核**：所有預算變更、手動解除操作皆留稽核軌跡

### 2.2 成功指標
| 指標 | 目標值 |
|------|--------|
| AI 成本即時性 | 當月累計金額誤差 < 5% |
| 告警送達時效 | 門檻觸發後 Email + 站內通知 5 分鐘內送達 |
| 降級生效速度 | 達 80% 後 1 分鐘內停止新 AI 生成 |
| 權限隔離 | 一般 admin 存取頁面必須 403，0 例外 |
| 稽核完整度 | 100% 的預算變更與手動解除操作寫入 admin_audit_log |

## 3. 目標用戶

**主要用戶**：Super Admin（CertiMate 創辦人 / CTO 級角色）
**次要用戶**：財務分析師（僅能看統計報表，不可修改預算）
**排除用戶**：一般 Admin、B2B 機構管理員、一般 User（完全不可見）

## 4. 功能範圍

### 4.1 In Scope
| 功能 | 說明 |
|------|------|
| F1. 成本總覽頁 | 四張卡片顯示 Anthropic / Gemini / Voyage / GCP 當月金額、預算、百分比 |
| F2. 供應商詳情 | 點進單一卡片看 token 級明細、30 天趨勢 |
| F3. GCP 服務分類 | BigQuery Billing Export 依服務降冪排列 |
| F4. 趨勢圖 | 30 天每日成本堆疊折線圖（Recharts） |
| F5. 預算設定面板 | Super Admin 可調整各 scope 的月預算與三級門檻（50/80/100%） |
| F5a. 整體預算即時調整 | 頁面頂部「整體調整」區塊：支援 `±N%` 按鈕與「設為固定金額」輸入框，點擊後依現有 scope 比例自動等比分配，仍可再個別微調；範圍限制 −50% ~ +200%，需二次確認 + 原因，寫入 `BUDGET_GLOBAL_SCALED` / `BUDGET_GLOBAL_SET` 稽核記錄（含 before/after 完整快照） |
| F6. 告警紀錄 | 顯示告警歷史（WARNING / DEGRADE / DISABLED） |
| F7. 手動解除停用 | 二次確認 + 原因輸入，寫入稽核 |
| F8. Voyage 配額鎖與降級佇列 | 應用層事前攔截機制。達 80% 門檻時新資源進入 `PENDING_BUDGET_RECOVERY` 狀態等待預算恢復（既有查詢不受影響）；達 100% 時硬性拒絕呼叫。Super Admin 擴充預算後佇列自動恢復處理。**預留接口**：`resource_chunks` 新增 `embedding_provider` / `embedding_model` 欄位，為未來多 provider 並存（雙軌向量庫）保留技術空間 |
| F9. 告警通知 | Email + 平台管理後台站內通知 + 儀表板紅色徽章 |
| F10. GCP Native Budget 單向同步 | Super Admin 在網頁調整 `AI_GEMINI` 或 `GCP_TOTAL` 預算時，後端自動呼叫 `billingbudgets.googleapis.com` 建立或更新對應的 GCP Native Budget，作為第二層告警護欄。`AI_ANTHROPIC` 與 `AI_VOYAGE` 因不在 GCP 計費範圍內不同步。同步失敗不阻擋本地更新（graceful degrade）。此為 **單向推送**（app → GCP），若使用者直接在 GCP Console 改動 Budget，app 不會反向同步，由心跳 drift detection 提示 |

### 4.2 Out of Scope（本版不做）
- 租戶層級的成本分攤（此為平台層級監控）
- 行動裝置原生 App 推播
- 多幣別支援（固定 USD）
- 成本分攤至個別 feature（僅供應商層級）
- 預測性告警（ML 預測未來超支）

## 8. 依賴與風險

### 8.1 技術依賴
- GCP Billing Export 必須先手動啟用並等待首批資料（約 24h）
- Anthropic Admin API 需 Organization 權限（非 Workspace key）
- Gemini embedding 備援方案需驗證向量維度相容性（1024 vs 768）

### 8.2 風險
| 風險 | 影響 | 緩解 |
|------|------|------|
| BQ 查詢本身產生費用 | GCP 成本上升 | 查詢結果快取 1 小時 |
| Anthropic API 當月帳單更新延遲 | 金額誤差 > 5% | 以應用層 token tracking 作為即時補強 |
| 備援 embedding 維度不相容 | 降級路徑失效 | AI/ML 工程師需先驗證，若不可行改為暫停新資源處理 |
| Super Admin 帳號被盜 | 可關閉所有 AI 功能 | 解除停用操作需二次確認 + 寫稽核 |
